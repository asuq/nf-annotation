# v0.5.0 qualification

## Scientific scope

FastAAI adds independent genus-scale clustering at 65% estimated AAI. Both domains
use complete linkage and remain separate. Existing canonical proteins preserve
the selected genetic code; FastAAI gene prediction is not used. Representatives
share the existing weighted quality components and tie cascade, excluding
centrality. Missing scoring metrics do not remove cluster memberships.

This is operational grouping, not a validated universal genus classifier. ANI's
representative choices and scores were checked against frozen v0.4.8 controls for all three
score profiles. Production jobs, inputs, publications and work/cache were untouched.

Public RefSeq inputs and exact compressed-file hashes are recorded in

The native controls recovered 80, 62, 88 and 88 markers respectively.

Eight unordered comparisons matched the unmodified upstream implementation at
its reported precision, with identical shared-marker counts and censored values.
The candidate used readable protein IDs such as `GCF_000005845_2__p000001`;
the upstream control used original RefSeq protein IDs. Additional zero-marker
and no-gene-prediction controls passed. Native comparisons
used four CPUs, 4 GiB and no network in a Linux amd64 container, emulated on the

accuracy across taxonomic groups.

Native testing exposed two upstream convenience-path problems: an empty-marker
handling error and a crystal-database binary/text merge error. The integration
uses native preprocessing methods directly and the standard protein-plus-HMM
database builder. Cached profiles retain selected proteins and their original
HMM hits, so database construction performs neither gene prediction nor HMM search.

## Functional checks and publication status

Focused controls cover threshold boundaries, linkage chains, missing/censored
evidence, empty/singleton cohorts, stable ties, missing representative metrics,
profile corruption and method/input invalidation. Workflow controls cover 16S
independence, threshold/scoring resume, portable successor profiles, source-reference
materialisation and reannotation retention.

The final regression gate covers 692 discovered test IDs: 685 passed and seven
optional image-build controls were skipped. Tests were run in two shards; after
updating stale fixture callers and assertions, affected and unfinished checks were
continued. Coverage was reconciled against discovery with no missing test IDs.
Fresh and resumed stub smoke runs from an archive of implementation commit
`ce554dd` passed. Both ANI and FastAAI comparison tasks were cached on resume,
with zero repeated marker extractions. These are workflow smoke checks, separate
from the fresh native qualification above.

Fresh Linux validation passed 88 helper controls. Fresh native FastAAI validation
matched all eight pinned-upstream pair controls, including readable protein IDs,
zero markers and the no-gene-prediction control. Repository helper integration and
Viper configuration checks passed. Viper retains its existing executor-scope
warnings and login-node limits. The controller design target is 32 CPUs and at
least 100 GB RAM; no controller resource defaults were added to profiles.

Adversarial regressions now cover literal shell identifiers, final reference
acceptance, full-update resume with functional outputs, changed cohort evidence,
invalid scoring candidates, interrupted profile copying and exclusive database
locking. Scheduling controls prove that AAI preparation starts before a held BUSCO
job completes and that slow early validation jobs do not stall later work.

Release packaging changes the image reference and documentation only. Exact
release-commit smoke and published-image checks are recorded in the GitHub
release notes. v0.4 publications and caches are intentionally unsupported;
start fresh v0.5 QC publications.

## Adverse-review performance controls

- Functional source validation performs zero extra payload hashes after its
  fingerprint scan; the earlier two-genome fixture performed 25.
- An unchanged import hashes its 16 destination files and performs zero source
  payload rereads, instead of hashing both sets of 16 files. Fresh source digests
  retain portable mode/size/timestamp guards across worker mounts.
- Aggregation reads each complete result JSON once using producer-supplied keys.
  Normalisation checks the planned manifest and consumed protein/coordinate
  tables; full bundle validation remains at planning/publication boundaries.
- The small AAI workflow requests one CPU and 3 GiB, rather than a large native
  comparison allocation. Memory requests scale with the actual input size.
- Persistent Barrnap failures make three native attempts instead of nine.

These controls establish removed work and resource requests, not an end-to-end
HPC speedup. Production was not rerun.

## Earlier development measurements

These are local engineering measurements with uncontrolled OS caches and concurrent
host load. They do not predict shared-filesystem or HPC turnaround.

| Control | Measurement |
| --- | --- |
| One real protein input, first preparation | 7.336 s; one native extraction |
| Same input and method, resumed preparation | 0.038 s; zero extractions, one cached profile |
| Protein input / published profile bytes | 219,704 / 19,164 bytes |
| Maximum native worker RSS | 136.5 MB; per-worker maximum, not aggregate batch memory |
| Synthetic 2,500-genome clustering | 3,123,750 pairs; 0.303 s |
| Condensed vector / process peak RSS | 25.0 MB / 166.7 MB |
| Binary pair-evidence bytes | 31.3 MB, including accession ordering |
| Two bacterial genomes: database / query | 9.415 / 2.056 s |
| Two archaeal genomes: database / query | 8.731 / 1.785 s |

The cache control uses a frozen real RefSeq proteome and explicitly synthetic QC
metadata. The clustering control uses synthetic pair evidence and excludes input
file generation from its timed call. Generation mappings are closed before
clustering; RSS is the whole process high-water mark, not a separately isolated
clustering measurement. The earlier text prototype took 33.296 s on this synthetic
case, about 110 times longer, but used 7.2 MB compressed evidence and 118.2 MB RSS.
The binary tradeoff removes parsing and duplicate accession strings, while this
highly repetitive synthetic text compressed better. Profile reuse removed the
HMM search and cut this one-input preparation time by about 99.5%. Neither ratio
is an end-to-end speedup; first-run AAI adds work to the pipeline. Native comparison
controls separately record database and query durations. Complete linkage still
has quadratic storage requirements.

Reproduction commands are provided by `tests/qualify_fastaai.py` and
`tests/benchmark_aai.py`. Source publications are immutable inputs; cached marker
profiles are copied independently into successor publications. No old-cache
upgrade adapter is provided.
