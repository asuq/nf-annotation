# nf-annotation v0.4 development and release specification

**Status:** The ultra-sensitive five-genome reference passes; the requested sensitive-mode setting is implemented and under native comparison.

**Recorded:** 2026-09-11.

**Target release:** v0.4.0.

**Inspected baseline:**
[`082a0687ead2ff481a151a9b4d579cac32b0a1a2`](https://github.com/asuq/nf-annotation/commit/082a0687ead2ff481a151a9b4d579cac32b0a1a2),
the v0.3.1 preparation commit.

This document is the canonical development plan for the functional-annotation
release. It consolidates the preceding technical review and the approved
decisions. The entrypoints, parameters and outputs described as new below are
requirements for development, not commands already available in v0.3.1.

The approved design is implemented through shared annotation planning, native
execution, normalization, cohort aggregation and `reannotate.nf`. The current
locked suite completed successfully: 541 tests, with seven optional container
tests skipped, plus helper integration and Viper configuration checks. Synthetic native-output
integration covers full-cohort execution, source-only reuse after work deletion,
renormalization, database invalidation, native failure publication and the final
gate. Real positive/zero controls pass for all five core callers, including
eggNOG replay with the native EC namespace and malformed COG fields handled
explicitly. EggNOG full-resource preparation passed SQLite integrity, full native-cache
comparisons and DIAMOND validation. Fresh G37 output provides a validated
522-protein, code-4 bundle. All five callers pass on that protein set, and the
recovered cohort passes independent checks of all six matrices, master counts,
coordinates and CRISPR controls. Native mixed GO-namespace confidence also
passes a per-gene comparison. All five ultra-sensitive reference genomes now
pass independent reconciliation. The subsequent requested sensitive-mode change
passes the native 50-protein control and is undergoing full-proteome and pooled
comparison. The scaling suite covers shared batch publication, parser-only
renormalization, portable reuse, membership/input invalidation and native failure
propagation through real Nextflow executions with synthetic caller outputs. The
[qualification record](v0.4_qualification.md) distinguishes native and synthetic
evidence and records measured resources. These checks are development evidence; the
release gates below remain open until all required evidence is reviewed.

## Release scope and defaults

v0.4 provides complementary annotation of a shared, code-aware protein set,
auditable evidence, and reusable cohort outputs for downstream analysis.

| Component | Decision |
| --- | --- |
| Backward compatibility | Clean break. No v0.3.x result importers, old-schema adapters, legacy aliases or eggNOG v2 runtime branch. |
| Upstream biology | Preserve the gene-prediction method, QC thresholds and ANI methods, including `--ani_allow_incomplete_16s` (default `false`). Default genetic-code selection to the paired mean-gene-length ratio rule below; retain the two completeness-difference rules as explicit options. Keep Codetta's specialised resource separate from direct Pfam. |
| Core functional analyses | eggNOG v3 only, COGclassifier, direct Pfam and KOfamScan. Enable the full core set by default. |
| Defence evidence | Retain PADLOC calling, pin its database, and normalize systems and member genes. Validate CRISPRCasFinder coordinate integration. |
| Analysis population | All eligible proteins in the declared cohort, including non-representative genomes. Do not run new tools only on eggNOG-negative proteins or new cohort additions. |
| Reannotation and updates | Support validated v0.4 bundles, reuse, renormalization and backfilling. No dependency on an old Nextflow work directory. |
| MGE markers | Omitted from v0.4. The independent resource and interpretation gate below is not satisfied. |
| Deferred work | InterProScan, an additional defence caller, RNA-aware defence extensions, full MGE regions/cargo/disruption, mobility/activity claims and pathway completeness. |
| Performance | The requested scaling candidate uses deterministic whole-proteome eggNOG batches, bounded native concurrency, JSON path lists and SQLite aggregation spooling. Native pooling requires measured benefit and equivalence checks before release. No protein deduplication is introduced. |

Remove superseded code, tests, configuration and documentation within the
changed scope when implementing the replacement. Permission for a clean break
does not require changing unrelated methods or deleting historical results.
The baseline commit remains a scientific reference, not a compatibility target.

### Genetic-code selection

The default v0.4 rule, `--gcode_rule mean_gene_length_ratio`, uses the paired CheckM2 `Average_Gene_Length` measurements
from translation tables 4 and 11. Define `R = mean_length_4 / mean_length_11`,
using the reported values without rounding before comparison:

| Valid paired result | Selected translation table |
| --- | --- |
| `R > 1.5` | 4 |
| `R <= 1.5`, including exactly 1.5 | 11 |

Both reports must pass validation, refer to the same genome, and contain finite,
strictly positive mean lengths. Missing, failed, inconsistent or invalid reports
leave the code unresolved and block dependent annotation. Defaulting to 11 for
a valid ratio at or below the threshold does not convert a failed comparison
into valid evidence.

Retain `--gcode_rule strict_delta` and `--gcode_rule delta_then_11` as selectable
criteria. Both select table 4 when its completeness exceeds table 11 by more
than 10 percentage points, and table 11 for the opposite advantage. At an
absolute difference of 10 points or less, `strict_delta` leaves the code
unresolved; `delta_then_11` selects table 11. All three rules require valid,
consistent report pairs. An invalid pair must not enter the default-to-11 case.

Keep paired completeness, contamination and coding-density measurements
as diagnostics. Calculate `Low_quality` from the selected code's existing
score, `completeness - 5 * contamination <= 50`; changing code can therefore
change QC and ANI eligibility even though the QC threshold is unchanged.

Record both mean lengths, the ratio, rule identity, selected code and selection
reason. The length-ratio threshold is `1.5` for the default rule and `NA` when a
completeness rule is selected. The retained rules have a fixed strict 10-point
threshold, recorded in their selection reasons and software contract. Reject
cohort reuse when the source rule differs from the requested rule, even if the
selected table happens to match. Retain Codetta's native inference and evidence-strength
information separately. Discordant Codetta evidence is a review flag and does
not automatically override the ratio rule. Potential contamination, unusual
gene structure and other exceptions require supporting evidence; discordance
alone is not a contamination diagnosis.

The 1.5 threshold is an empirically selected operational criterion, not a
published universal cutoff or an independently validated accuracy claim. Keep
the private cohort audit and its source provenance in ignored local records.
Qualification must cover ratios below, at and above 1.5; missing/non-positive
lengths; failed or inconsistent report pairs; and the effect of code changes on
downstream QC, translation, annotation and reuse. Changes to genetic-code
selection invalidate affected protein bundles and their dependent analyses.

Low-quality genomes remain eligible for annotation when their selected code and
protein bundle are valid. Missing or partial 16S continues to affect ANI through
the existing user-controlled gate, independently of annotation eligibility.

## Workflow and input contracts

### Entrypoints and orchestration

| Interface | Intended contract |
| --- | --- |
| `main.nf` | Full genome workflow, including core annotation, the master table and matrices. Cohort updates use the complete revised sample manifest and validated v0.4 source results. |
| `reannotate.nf` (new) | Annotation-only execution from a validated v0.4 results manifest, including protein bundles and the source master-table information. Refresh functional outputs without requiring QC, ANI or taxonomy databases. |
| `prepare_databases.nf` | Prepare and validate the compatible resources for enabled tools before sample execution. Extend the existing preparation workflow. |
| `--annotation_tools` (new) | An explicit tool list, defaulting to `eggnog,cogclassifier,pfam,kofam,padloc`. Unknown names and missing resources for enabled tools fail preflight. MGE markers require explicit inclusion when available. |
| `--annotation_from` (new) | The source v0.4 published results for the annotation-only entrypoint. Reject unsupported bundle/schema versions explicitly. |

Keep separate entrypoints with shared bundle preparation, functional annotation,
defence normalization and aggregation subworkflows. Use named DSL2 emits and
keyed tuples. Wire emitted handles directly; do not discover downstream inputs
through asynchronous `publishDir` output or join by channel arrival order.

Initially support pipeline-generated v0.4 bundles only. Arbitrary external
FAA/GFF import is outside this release. Reannotation must retain the source
genome information needed for its rebuilt master table and replace the affected
functional columns. It must not silently recalculate upstream methods or infer
missing QC values. A source missing required published artefacts is incompatible.

Keep the existing main-workflow sample and metadata inputs unless a changed
contract requires an explicit replacement. Record the selected accession set
and tool list in the analysis plan. Remove the old hidden eggNOG-only debug
selection from the v0.4 annotation execution path; any intentional subset must
be declared and reflected in statuses and comparison denominators.

### Canonical protein and coordinate bundle

Build bundles only from successful, validated Prokka outputs. Preserve the
original FAA/GFF/GBK, selected translation table and source provenance.

- Use a canonical gene identity based on accession plus original protein/locus
  identifier. Keep original IDs and a reversible mapping to any compact tool ID.
  Neither a truncated locus tag nor a description-derived ID establishes
  uniqueness across genomes.
- Record protein sequence length/checksum, source-file checksums, contig ID and
  length, strand, genetic code, and ordered CDS segments. Record topology when
  available; do not invent it when unknown.
- Use 1-based closed genomic coordinates, matching GFF. Label protein-domain
  coordinates separately and convert other coordinate systems at their adapters.
- Preserve compound features, negative strands, circular-origin features and
  partial-CDS metadata. Never invent adjacency across contigs.
- Validate FAA identifiers, GFF feature relationships and sequence provenance.
  Reject unexplained duplicate or orphan IDs. Preserve biological relationships
  explicitly rather than forcing all feature types into a universal bijection.
- Do not retranslate the supplied proteins in functional tools. Preserve code-4
  and code-11 source translations, including internal tryptophan encoded by UGA.

Genome quality, annotation eligibility and ANI eligibility are distinct. An ANI
exclusion must not remove an otherwise eligible protein bundle from annotation
or its genome from downstream summaries.

An empty or zero-record FAA fails bundle validation as `incompatible_input`,
with an `empty_proteome` reason. This is distinct from successfully analysing a
non-empty protein set and obtaining zero hits.

The implemented bundle module publishes `samples/<accession>/annotation/bundle/`
with the original FAA/GFF/GBK and genome, a compact-ID `proteins.faa`,
`protein_manifest.tsv`, `gene_coordinates.tsv` and checksummed `bundle.json`.
GenBank translations and translation-table qualifiers must agree with the FAA
and selected code. GFF and GenBank coordinates must agree; compound segments
follow GenBank biological order, with fuzzy locations and native qualifiers
retained. Unknown topology remains `NA`. Input-protein and coordinate identities
are separate. Unit controls, a two-code Nextflow stub workflow and all five native
bundles pass. Independent translation audits reconcile all 6,157 proteins with
native Prokka DNA; the OY-M source-masking difference is recorded in the
[qualification record](v0.4_qualification.md). The ultra-sensitive cohort passes
functional acceptance; the changed sensitive-mode cohort remains pending.
The final annotation acceptance gate passes successful and failed native-output
integration controls.

## Status and failure handling

`annotation_status.tsv` is authoritative for annotation outcomes, with one row
per accession/supported-tool pair in the declared analysis plan, including
disabled and deliberately unselected combinations. Derive annotation fields in
`sample_status.tsv` and the master table from it. Existing QC and ANI status
logic can retain its own responsibilities; do not redesign unrelated reporting.

| State | Meaning |
| --- | --- |
| `success` | Execution completed and required outputs, schema and identities were validated. Zero accepted hits is valid. |
| `failed` | Execution or required output validation failed. |
| `skipped_disabled` | The tool was deliberately disabled. |
| `skipped_not_selected` | The accession was deliberately outside the declared analysis selection for this tool. |
| `upstream_failed` | A requested analysis could not run because required upstream processing failed. |
| `incompatible_input` | A source bundle or resource violates the supported input contract. |

Record the reason, actual exit code when available, known input-protein count,
returned/accepted counts where valid, validated schema, analysis fingerprint and
field-validation flags. Unknown values remain missing. A file, a directory or
a scheduler exit code alone does not establish scientific success.

Fail global configuration, identifier-contract and resource incompatibilities
before expensive work where possible. For failures during independent sample
analyses, complete unaffected work, block dependent work, and retain diagnostics.
Publish available results with explicit completeness/status information, then
return a non-zero workflow outcome if any requested analysis failed, had an
upstream failure or encountered incompatible input. An optional tool becomes a
required analysis for the selected samples once explicitly requested.

The final acceptance step must check the planned accession/tool combinations,
not only rows that happened to arrive. A missing status row cannot become a
successful omission. If a fatal engine failure prevents final aggregation, the
run remains incomplete; do not publish a completion assertion.

Use bounded retries only for classified transient failures. Avoid nested retry
loops and retries of deterministic schema, ID or database errors. A failure must
not cause a switch of tool version, database or annotation method.

An invalid optional annotation field does not invalidate the tool's other valid
fields. Preserve the original value, record a field-specific error, and mark
dependent summaries or matrix values for that genome and source as `NA`.
Do not silently omit the malformed value and publish an apparently complete
count. Keep unaffected assignments and summaries usable. The tool may retain
`success` with explicit field-validation flags when its required outputs,
schema and identities pass validation. Missing required columns or metadata,
broken gene identifiers and other whole-result contract violations still fail
the tool's result. Test that each field error makes every dependent output
unavailable while preserving independent valid fields.

## Scientific annotation contracts

### eggNOG v3

Use a single v3 integration with compatible eggNOG 7 resources. The frozen
runtime is v3.0.0-beta6 with eggNOG 7.0.0; native positive/zero controls and
all five ultra-sensitive reference proteomes pass. The selected sensitivity
change below is under native comparison.
Its release notes describe changed DIAMOND options, removed fields including
`Description`, and confidence codes decoded by an output-header legend.
[Release notes][eggnog-release] and [versioned usage][eggnog-usage].

Parse native output before stripping comments. Validate column names, declared
schema and query IDs; preserve donor context and the confidence legend. The
native `annotation_confidence` labels describe the annotation's source and
orthology relationship; they are not calibrated probabilities. Do not substitute
another field for the removed description without naming its actual source.

Include only native `high` and `medium` confidence in the primary eggNOG
functional summaries and count matrices. Preserve `low` annotations in the
detailed evidence with their original confidence and exclusion reason. Apply
this policy independently to each annotation field, not to an entire protein.
Decode confidence using the native header legend; unknown or malformed values
must not become accepted annotations. Record this filtering policy in output
provenance and analysis fingerprints.

The accepted GO policy applies `high` and `medium` separately to molecular
function, biological process and cellular component. The candidate v3 engine
combines these GO namespaces and reports only their best confidence in the
native merged field. Export each namespace's terms and already-computed native
confidence before that merge, then apply the filter separately. Preserve the
unaltered native output alongside this additional evidence. Do not infer the
separate confidence values from the merged label or change how eggNOG selects
annotations. Pin and record the export modification and GO ontology resource.
Qualification must verify the exported values against the engine's selections
and cover a protein with high-, medium- and low-confidence GO categories,
including missing categories and consistency across enabled execution modes.

Validate COG categories against the resource vocabulary, including valid
multi-letter categories and missing-value conventions. Keep malformed native
values and validation flags, and mark affected category summaries unavailable
under the optional-field policy above. The earlier review recorded a web-service
report in [issue 616][eggnog-cog-issue]; that is a
regression-investigation input, not proof of a local failure or a verified fix.

Make search sensitivity, iteration, donor restrictions and ortholog reporting
explicit. Initial five-genome qualification used the ultra-sensitive ceiling
with iteration enabled and provides the retained comparison reference.
For the requested 10,000-sample target, the selected setting is now `sensitive`
with iteration enabled, matching the pinned eggNOG v3 default. Native comparison
of the changed setting and larger-cohort performance qualification remain
required; passing five genomes does not establish that scale. Bound memory
using allocated task resources rather than host-wide RAM.
Keep transferred Pfam evidence source-labelled; do not enable a second full
de novo Pfam scan inside eggNOG by default.

### COGclassifier

Qualify COGclassifier v2.0.0 with its COG2024 resources. Retain native RPS-BLAST
evidence and mappings. Use the documented E-value of 0.01 as the initial search
setting, recorded explicitly. Preserve native best-hit behaviour while testing
ties, including E-values represented as zero. Do not add a universal coverage
filter without biological justification. [Documentation][cog-docs] and
[release][cog-release].

The native classifier uses the first letter for multi-category assignments.
Reconstruct the full ordered category set from the pinned definitions and retain
the native primary category. Keep categories R and S as valid assignments.
Publish multi-label category counts and clearly named fractional counts, using
weight `1/k` for each of a gene's `k` categories. Fractional weighting is a
reporting convention, not a biological weighting claim. COGclassifier supplies
the master table's primary COG-category summaries.

### Direct Pfam

Use a pinned, validated Pfam-compatible wrapper with HMMER and the library's
curated gathering thresholds and clan/overlap semantics. The approved approach
does not introduce a bespoke clan resolver. Qualify the exact wrapper source,
HMMER version, model metadata and resource bundle together. The upstream
[PfamScan distribution][pfamscan] supplies the frozen 1.6 wrapper. The
qualified image preserves raw alternatives before its native post-processing;
its provenance records the upstream archive and narrow output-retention patch.

Pfam 38.2 is the prepared, checksummed resource; native positive/zero controls
and all five proteomes pass. The version is also documented in official
[InterProScan release notes][pfam-version]; this does not introduce an
InterProScan dependency. The [qualification record](v0.4_qualification.md)
records exact resource and image identities. A moving archive URL is not a
resource pin.

Retain native evidence for raw alternatives and resolved architectures: family
accession/version, sequence and domain scores, relevant E-values, protein/HMM
coordinates, clan and acceptance state. Verify evidence retention in the chosen
wrapper and record any narrow adaptation. Preserve repeated and nested domains.
A generic same-clan deletion rule is not an adequate substitute for validated
post-processing. See [Mistry et al.][pfam-paper] for methodological context.

### KOfamScan

Qualify KOfamScan v1.3.0 with a checksummed profile/`ko_list` bundle. The accepted
search scope is prokaryotic profiles only. Freeze the exact prokaryotic subset
list with the resource bundle and examine controls that might expose omissions.
Retain candidate hits, family thresholds, score types, scores, E-values and
threshold availability. Respect the resource's
score type; do not replace its acceptance criteria with a single best E-value.
[Versioned documentation][kofam-docs] and [resource service][kofam-resource].

Distinguish threshold pass, threshold fail, threshold unavailable and no reported
hit. Preserve multiple accepted KOs. No below-threshold rescue enters the primary
results, and any additional E-value filter must be explicit and fingerprinted.
Record actual process/thread concurrency and scratch use; the CPU option controls
simultaneous searches. eggNOG and KOfam KO evidence remain separate, and their
agreement is not independent statistical confirmation.

### Defence evidence

Keep PADLOC's existing protein/GFF calling method and normalize both systems and
member genes. Continue using a bundled database, but replace the floating build
update with an immutable resource identity and checksum. Do not count generic
HMM matches or member rows as complete systems. [PADLOC documentation][padloc].

Join members to the canonical coordinate bundle. Count each distinct
accession/system-ID pair once and preserve repeated system numbers across
genomes. Normalize retained v0.4 output only when its fingerprint is compatible.
Validate CRISPRCasFinder joins through coordinates. Do not infer RNA-aware
PADLOC coverage from FAA/GFF input or replace a caller-specific RNA input with
unvalidated CRISPRCasFinder output.

### Optional MGE-associated recombinase candidates

This branch is omitted from v0.4. The requirements below preserve the approved
boundary for evaluating the feature; no MGE tool name, parameter or output is
advertised by the implemented workflow.

The marker branch is inspired by the recombinase-based work of
[Khedkar et al.][mge-origin] and [Guo et al.][mge-paper]. Reusing this pipeline's
code-aware proteins is an intentional adaptation of the published workflow.

Recover the complete 68-profile collection, thresholds, class mapping and
licence before implementing the advertised feature. Reconcile the article's
[data record][mge-data] with the [author-code record][mge-code] and its earlier
[data release][mge-earlier-data]; do not infer matching bytes from filenames.

Search the complete model set, retaining competing cellular models and raw
alternatives. Apply deterministic best-model/tie rules and versioned evidence
filters after searching. Preserve `raw_candidate`, `accepted_candidate`,
`ambiguous_candidate`, `rejected_candidate` and `needs_review` states, with rule
IDs and evidence-availability flags. A missing functional/Pfam analysis cannot
silently satisfy a filter. Avoid global keyword blacklists and forced class
assignments for ambiguous or truncated proteins.

Ship only after real positive/zero-hit tests, auditable rejection rules and
relevant controls pass. Otherwise omit the feature and its advertised interface
from v0.4. A request for an unavailable feature must fail preflight.

Report marker candidates and their coordinates, not intact MGE abundance,
element boundaries, defence cargo, insertion disruption or demonstrated
mobility. No candidate classification removes the same protein's independently
supported defence evidence.

## Outputs for downstream analysis

### Master table and supporting evidence

`tables/master_table.tsv` remains a required, central deliverable with one row
per genome. Retain metadata, taxonomy, QC, genetic code, CRISPR and ANI information
and add functional summaries. Version the changed contract and reject duplicate
accessions or metadata/derived-column name collisions.

Add input/analysed-protein counts, source-specific annotation coverage and
denominators, annotation completeness and tool statuses, COG category counts,
PADLOC system totals, and MGE-marker totals when that feature ships. Define
coverage separately for mapped proteins and accepted functional assignments;
an eggNOG seed hit alone must not be silently counted as an assigned function.

| Published output | Unit and purpose |
| --- | --- |
| `tables/protein_manifest.tsv` | Every input protein, including those without hits; original/canonical IDs, sequence provenance and coordinate join key. |
| `tables/gene_coordinates.tsv` | Ordered feature segments, contigs, strands and genomic coordinates. |
| `tables/protein_function_summary.tsv` | One row per input protein; source-labelled assignments, availability/status and coordinates or their join key. |
| `tables/eggnog_annotations.tsv` | Normalized v3 evidence and references to its native metadata. |
| `tables/cog_assignments.tsv` | COGclassifier assignments, complete ordered categories and search evidence. |
| `tables/pfam_domains.tsv` | Domain matches, coordinates, scores and acceptance state, including retained alternatives. |
| `tables/kofam_hits.tsv` | KO candidates and threshold/acceptance evidence. |
| `tables/defence_systems.tsv`, `tables/defence_genes.tsv` | Systems and their member-gene relationships. |
| `tables/mge_markers.tsv` | Optional candidate genes, model alternatives and classification evidence. |
| `tables/annotation_status.tsv` | Authoritative accession/tool execution outcomes. |
| `tables/annotation_provenance.tsv` | Search and normalization fingerprints, resources and parameter/schema context. |

Retain native tool outputs and metadata under the existing per-sample hierarchy.
Use shared aggregation code for master-table summaries and matrices so their
counts cannot diverge. A separate duplicate genome-summary table is unnecessary
when the master table already carries those values.

For example, a protein with two Pfam domains in a three-gene defence system
contributes once to each relevant protein/family count and the system contributes
once to the genome's system total. The domain and membership tables preserve
the supporting rows. Never join these rows directly into the master table in a
way that duplicates genomes or inflates counts.

### Ready-to-use functional matrices

Publish these TSV matrices under `tables/functional_matrices/`:

| Matrix | Cell definition |
| --- | --- |
| `eggnog_ko_counts.tsv` | Distinct proteins with an accepted eggNOG assignment to the KO. |
| `eggnog_go_counts.tsv` | Distinct proteins with an accepted eggNOG assignment to the GO term, using the separate GO-namespace confidence filter. |
| `eggnog_ec_counts.tsv` | Distinct proteins with an accepted eggNOG assignment to the EC number. |
| `kofam_ko_counts.tsv` | Distinct proteins with an above-threshold accepted KOfam assignment to the KO. |
| `cog_counts.tsv` | Distinct proteins assigned to the COG by COGclassifier. |
| `pfam_gene_counts.tsv` | Distinct proteins carrying an accepted domain from the Pfam family. |

Every matrix has an `accession` column followed by feature IDs, and shares the
master table's selected genome set and ordering. Use the sorted union of
accepted feature IDs observed in that cohort as the feature axis. Publish a
`feature_catalogue.tsv` giving matrix, feature ID, definition and source/resource
identity. Feature axes may expand when cohort membership changes; use the
catalogue rather than assuming columns are identical between cohorts.

Deduplicate each accession/protein/feature combination before counting. Repeated
Pfam domains on one protein count once in the gene matrix and remain repeated
in domain evidence. Multiple accepted KOs can contribute to several KO columns;
column sums need not equal the number of analysed proteins. Do not merge the
two KO sources or compare their raw scores as a common scale.

For GO, count the accepted terms returned by eggNOG without adding parent or
ancestor terms from the ontology. Preserve any ancestor terms already present
in the native assignments; do not silently remove them or label the result as
leaf-only GO annotation. The ontology supports namespace validation and feature
definitions, not additional assignment expansion.

Use `0` for no accepted detection only after a validated successful analysis.
Use `NA` for unavailable values, with the reason in authoritative status. Never
drop a genome because a tool failed. An entirely zero-hit cohort retains all
accession rows even if no feature columns are observed. Ratios with an unknown
or zero denominator remain `NA`; do not fabricate annotation fractions.

These are functional gene-count matrices, not read-abundance measurements or
pathway-completeness estimates. Preserve raw counts; any later normalization
must state its denominator and interpretation.

## Resources, provenance and reuse

Extend the existing database preparation workflow and canonical manifest. Do
not build a new database service. Prepare resources before sample jobs and
verify that concurrent analysis is read-only and works without network access.

Freeze these bundles together:

- eggNOG annotation/search data, taxonomy, auxiliary data and prebuilt caches,
  with mapper compatibility and image identity.
- COG/CDD profiles, CDD-to-COG mappings, definitions and category descriptions.
- Pfam models, metadata, clan information and compatible search indexes.
- KOfam profiles, threshold/score metadata and the selected subset list.
- PADLOC models and rules, independently identified within its container.
- Optional recombinase profiles, class map and versioned filtering rules.

Maintain a separate Dockerfile and pinned runtime for each annotation tool.
Include each tool's required dependencies in its own image; do not combine the
functional callers into a shared runtime image. Qualify the exact images used
for sample execution and record their immutable identities.

Record upstream release/commit, acquisition source/date, licence, checksums,
format compatibility, validation outcome and software/image identity. Hash
resources during preparation/preflight, not once per genome. In-place content
changes and a stale manifest must be detected before reuse; a directory path,
user label or mutable tag alone is insufficient identity. Publish readiness
atomically so interrupted preparation cannot appear complete.

The candidate versions in this document are not completed resource pins.
Wrapper/library versions, container identities and all missing checksums must
be resolved and recorded before qualification. Do not update unrelated QC,
Codetta, BUSCO or taxonomy resources while preparing annotation databases.

Maintain separate dependencies for native-search reuse and normalized-result
reuse. Fingerprints cover protein content and identity, genetic-code provenance,
tool/container, resources, meaningful parameters, model subset and any relevant
search-space definition. Normalization additionally records parser/schema,
mapping and interpretation-policy versions.

Keep the full sample-analysis fingerprint separate from the shared method
identity. Different genomes naturally have different input fingerprints.
Comparability requires matching tool/resource versions, search settings,
search-space policy and interpretation rules, not identical protein inputs.

| Change | Required action |
| --- | --- |
| Protein content or identity | Rerun affected searches; for eggNOG this includes every member of a changed batch. Reuse compatible results for unchanged inputs and batch contexts. |
| Relevant search parameters or searched resources | Rerun the affected analysis across the selected comparison cohort. |
| Parser or reporting interpretation only, with sufficient valid native evidence | Renormalize without repeating gene prediction/search. |
| Metadata only | Rebuild metadata-dependent summaries; reuse unaffected searches. |
| Newly enabled tool | Backfill every eligible selected v0.4 bundle, including retained genomes. |
| Added/removed genomes | Follow the main cohort-update contract, reuse compatible v0.4 analyses, and rebuild cohort outputs. |
| Identical immutable resources relocated | Establish identity through the validated manifest; relocation alone is not a scientific method change. |

Publish an annotation plan before expensive work, listing each accession/tool,
intended run/reuse/renormalization/skip and reason. Reject incomparable mixed
method identities within each primary matrix. Preserve historical evidence
separately; do not fill new cohort tables with an unlabelled mixture of resource
versions.

## Validation and HPC qualification

### Required test scenarios

| Scenario | Acceptance condition |
| --- | --- |
| Descriptive headers, repeated locus tags and punctuation | Every result maps to exactly the intended sample/protein; no guessing underscore boundaries or cross-sample merges. |
| Valid and mismatched FAA/GFF; orphan/duplicate IDs | Valid bundles pass; inconsistencies fail with actionable reasons. |
| Paired mean-length ratios below, at and above 1.5; invalid or missing pairs | The accepted rule selects the expected code, preserves its inputs/reason, and fails explicitly on an invalid comparison. Selected-code QC and dependent annotation follow that decision. |
| Code 4, code 11 and a documented UGA-sensitive CDS | Original protein sequences and translation provenance are retained. |
| Empty protein input, zero hits, missing output, non-zero exit and missing status | Distinct explicit outcomes; no failure becomes a biological zero or disappears from acceptance. |
| Disabled/unselected tools and upstream failures | Correct statuses, denominators and final workflow outcome. |
| eggNOG v3 schema/legend and malformed COG field | Required metadata is preserved/validated; field quarantine is explicit and invalid categories do not enter counts. |
| Mixed GO confidence across molecular function, biological process and cellular component | Separate exported confidence controls each category; only high and medium contribute to primary counts, with no additional ancestor expansion. |
| Invalid optional annotation fields with other valid fields | Valid fields remain usable; every affected summary or matrix value is unavailable and carries an explicit reason. Required schema or identity violations still fail the tool result. |
| Multiple COG categories, R/S categories and tied best hits | Ordered memberships and reporting weights are correct; native ranking and ambiguity remain auditable. |
| Overlapping, nested and repeated Pfam domains | Accepted architectures follow the qualified wrapper; gene counts do not count domain repeats twice. |
| Multiple KOfam hits and absent thresholds | Alternative KOs and score types are retained; unsupported hits are not promoted. |
| Multi-gene PADLOC systems and repeated system numbers | Systems are counted by accession/system ID, with valid member coordinates. |
| Multiple contigs, negative strands and compound/circular features | Coordinates preserve their meaning; no invented cross-contig relationships. |
| Master table, matrices and source evidence | Genome keys/order agree; counts reconcile to distinct accepted proteins/systems; unavailable values remain `NA`; all-zero cohorts remain valid. |
| Read-only/offline resources and same-path database changes | No sample job downloads or updates data; stale/incompatible resources cannot be reused. |
| Parser-only changes, metadata changes and newly enabled tools | Renormalization, search reuse and retained-genome backfill work as specified. |
| Published results without work/cache directories | A validated v0.4 source is sufficient for supported reannotation/update operations. |
| Interrupted execution/resume and incomplete status sets | Valid results are reused deterministically; incomplete runs cannot pass acceptance. |
| Optional MGE cellular competitors, ambiguous models and missing evidence | Candidate states/reasons are correct; absent evidence never defaults to acceptance. |

## Release procedure and gates

### Candidate and publication sequence

1. Complete applicable work packages and review their focused diffs. Freeze
   source revisions, dependencies, resource manifests and scientific settings.
2. Build candidate containers for the compute architecture and record immutable
   identities. Test the same candidate artefacts locally and on OIST. Record
   OCI digests when available and SIF checksums for converted images. Do not
   confuse a mutable tag with either identity.
3. Complete the layered tests and five-sample qualification. Preserve evidence
   references, commands/settings, actual versions, measured resources and known
   limitations. Mark unavailable/skipped checks honestly.
4. Synchronize `nextflow.config`, `pyproject.toml` and the project entry in
   `uv.lock` for v0.4.0. Refresh dependency locks through their normal tools when
   necessary; avoid unrelated lock churn. Update the changelog, parameter/output
   contracts, README, architecture, database and operator/test documentation.
5. Check the final candidate commit against the tested code and artefacts.
   Rerun relevant checks after changes; code/container changes require matching
   rebuilt artefacts and renewed affected qualification. Prepare release notes
   describing the clean break, v3-only requirement, new outputs and limitations.
6. Obtain explicit release authorization before external publication, including
   candidate image publication if needed for distribution. Publish verified
   images, verify resolved digests and update/recheck final references as needed.
   Only then push the reviewed release commit, create/push the release tag and
   publish the release notes against that exact commit.
7. Verify a fresh checkout of the tagged release and the published container
   references with a small smoke run. Preserve the evidence. A correction to a
   published release requires an explicit subsequent release, not silent tag or
   resource replacement.

The documentation commit that introduces this plan does not authorize image
pushes, tags or release publication and does not change the pipeline version.

- [ ] COG multi-category counts, Pfam architectures and KOfam acceptance semantics pass their controls.
- [ ] PADLOC system/member joins and independent database provenance are correct.

- [ ] The required master table and source-specific matrices reconcile with detailed evidence and retain the selected genomes.
- [ ] Reannotation, backfill, reuse and invalidation work from published v0.4 outputs without legacy importers.
