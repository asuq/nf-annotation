# v0.4.6 fingerprinting qualification

Date: 2026-10-29. Baseline: v0.4.5, commit
`6e60ca05c963a1d5ab71042dd4680e277f0df245`.

## Scope

- One pool performs bounded parallel content reads inside the existing source
  fingerprint task. Directory enumeration and ordered digest assembly remain
  serial. Scientific validators and their code identity remain unchanged;
  the execution helper is separate from the validator modules.
- Fingerprint bytes, reference dependencies and requested source order match the
  serial implementation. Mutation checks include file descriptors and directory
  membership. Progress reports are outside fingerprint/receipt identities.
- No scientific method, database, image or dependency version changed. Existing
  v0.4.4/v0.4.5 releases and active production checkouts/jobs were not modified.

## Local read-only I/O control

`tests/benchmark_fingerprinting.py` creates four synthetic publications, then
performs read-only timing passes across 4,132 files / 1,075,838,988 bytes. Each
source contains eight 32 MiB files and 1,024 small tables. It loads the exact
v0.4.5 fingerprint function as its baseline and asserts identical records on
every pass. Python 3.12.13 ran on local macOS arm64 storage.

| Implementation | First pass, seconds | Reverse-order pass, seconds |
| --- | ---: | ---: |
| v0.4.5 serial | 1.843 | 1.376 |
| Bounded reader, 1 worker | 1.325 | 1.333 |
| Bounded readers, 4 workers | 0.807 | 0.784 |
| Bounded readers, 8 workers | 0.728 | 0.726 |

The run order was baseline, 1, 4, 8, 8, 4, 1, baseline. Caches were not flushed;
newly written inputs and repeat reads could be cached. Directory enumeration took
about 0.03 seconds per pass. These measurements demonstrate actual overlapping
reads and unchanged results on this local fixture, not linear CPU scaling,
shared-filesystem throughput or a guarantee for real genomes. No production
reads, Slurm submissions or native scientific runs were used.

## Regression controls

- Serial and 1/2/4/8-worker records and JSON bytes match; original source order is
  retained. A synchronised reader test reaches exactly four concurrent readers
  and verifies a pending window of at most eight reads.
- Same-size edits with restored mtime fail during a read and change the next
  fresh fingerprint. Directory additions, replaced leaves, reference cycles,
  missing/retargeted providers and shared dependencies are covered.
- Progress is readable while reads are blocked and reports final source, file
  and byte totals. Shared providers are hashed once per invocation.
- A real Nextflow fixture starts from the exact v0.4.5 fingerprint/configuration
  code, completes ANI, upgrades the changed files and resumes. ANI preparation
  and FastANI remain cached when requesting four readers under a two-CPU cap,
  and when subsequently changing to one reader.
- The upgrade test exposed unstable collector row order in v0.4.5. Reusing prior
  task tables only after matching fresh headers/row multiplicities fixed the
  unnecessary native rerun. Changed, duplicated or quoted/reordered rows cannot
  claim equivalence; unavailable retained tasks cause an explicit stop.

## Release gate

- The locked suite passed 636 tests with seven optional Docker skips.
- Helper integration, Viper configuration parsing, scoped Ruff checks, the offline
  lock check and diff whitespace checks passed. Viper retains its existing
  warnings about executor-scoped configuration keys.
- Six parallel-reader tests passed in the unchanged pinned Linux amd64 helper
  image, with networking disabled and four CPUs / 1 GiB requested. The host was
  arm64, so this is an emulated runtime compatibility check, not an I/O benchmark.
- Final committed-source smoke results are recorded in the GitHub release notes.
  Native scientific qualification from earlier releases is not counted as a new run.
