# v0.5.4 qualification

## Scope

Released Prokka 1.15.6 and Prodigal 2.6.3 remain unchanged. The existing Prokka
image is now pinned by digest:
`quay.io/asuq1617/prokka@sha256:d9ff718c4ea19621a16a78b9d21dc1d1073bcaadeef2348afa38c5544ed4564d`.
The helper remains at `36c4148f975aa76008e48214f4fea1dad8e78f9b`.
No new image was built. The upstream mode-selection bug remains. There is no
pre-Prokka quality gate, metagenome flag or sample-specific rescue invocation.

The workflow observes the actual prediction child, forwards its arguments and
output unchanged, and distinguishes failed prediction from successful zero CDS.
Bundles, sample status, reuse and genome reporting retain that distinction.
Codetta now publishes native entries separately so a cached task cannot delete
the summary owned by its summarisation task. Its native commands are unchanged.
The [repository policy](../tool_option_policy.md) records the command audit.
Fresh QC publications are required for the new prediction-outcome contract.

## Native controls

Isolated Linux/amd64 controls used the unchanged image, two CPUs, genetic code 11
and identical Prokka options: `--outdir prokka --prefix CONTROL --locustag CONTROL
--compliant --kingdom Bacteria --gcode 11 --cpus 2 --rfam`. Only input paths varied.
These are synthetic execution controls, not biological genome qualification.

| Input | Native result | Workflow result |
| --- | --- | --- |
| 8,500-bp short control | Prodigal exit 10; Prokka exit 0 | Prediction failed; protein count unavailable |
| 45,000-bp positive control | Both exit 0; one CDS | Successful one-protein bundle |
| 45,000-bp zero control | Both exit 0; zero CDS | `incompatible_input`, `reason=no_cds`, protein count 0 |

All three passed the real bundle CLI. The Prokka source MD5 remained
`4df8e8d694632f3f4dda01ce6fba38e6` before and after execution. The child retained
`-c -m -g 11 -p single -f sco -q`; no scientific arguments were overridden.
An initial homopolymer zero control also exposed an unrelated native Barrnap
alphabet error, so the accepted zero control uses all four bases and has no such
error. This release does not claim to fix other upstream tools' error handling.

For reproduction, write FASTA header `>control`, one sequence line and a final
newline. Generate the short sequence with `random.Random(544).choices('ACGT',
k=8500)`, then continue the same generator for 45,000 bases for the positive
sequence. The zero sequence repeats the following 90-base motif 500 times:

```text
ATTGTAACGGATACGTACTCTAGTATTACTTGCATTCGTGACGTTCCAAACTAATGTGTGCATGCTATTCTAACTCTGAACTGCTATTTT
```

The respective FASTA MD5 values are `2939ee1c97b5ca77d689487f686bd718`,
`bfb2dca63b6c065854220e250818fc5a` and `5571635ff4df63da31cbd53b2c35b469`.
Run `bin/run_prokka.py` with the options above in separate working directories,
append its exit status to each log as `exit_code=N`, then pass the native
FAA/GFF/GenBank and original FASTA to `bin/prepare_annotation_bundle.py`.

## Development checks

- The pinned Linux helper passed 32 observer, outcome and bundle tests, including
  nonzero exits, signals, missing execution evidence and inconsistent CDS counts.
- All 77 focused outcome, bundle, status, reuse and reporting checks passed.
  Known zero counts stay zero; masked failures cannot be reused as verified
  zero predictions.
- Repository-wide Ruff, formatting and ty checks passed, as did helper integration
  and Viper configuration checks.
- Rendered Nextflow commands passed for both domains and genetic codes 4/11,
  including empty-versus-missing FAA handling. The missing-FAA control failed
  before the workflow fix and passed afterwards.
- Locked discovery ran 733 tests, with seven opt-in container checks skipped.
  It initially reported 12 loopback-server permission errors, three stale
  contract assertions and one Codetta resume/publication failure. The 12 server
  tests passed with the required permission; all 84 affected configuration,
  module and integration checks passed after repair. Successful unrelated cases
  were not rerun.
- The Codetta regression reproduced deletion of a separately owned summary on
  resume. It now preserves that summary and nested diagnostics with the native
  call count unchanged. Reviewed-code QC, resume and cohort reuse also passed.

## Publication gate

Publication requires the observer, prediction-record, domain-command, Codetta
staging/resume and reviewed-code integration controls to pass from the release
commit, plus the final Ruff/ty checks. The GitHub release records the gate result.
These are workflow controls; they do not repeat native biological analyses.

Production jobs, data and caches remain untouched. Earlier releases and the
unpublished primary checkout are unchanged.
