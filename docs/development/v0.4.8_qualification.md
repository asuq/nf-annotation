# v0.4.8 qualification

## Scope

- Remove cohort protein-table reconstruction when functional searches are disabled.
- Stream full functional tables without SQLite; preserve ordering and all evidence.
- Reuse published QC assembly statistics for ANI.
- Share fresh fingerprint digests with semantic validation and keep readers busy
  independently of filename order.
- Parse the ANI matrix once for clustering and representative selection.
- Remove individual reuse's intermediate payload copy and obsolete cache-upgrade code.

Genetic-code selection, domain routing, ANI eligibility, complete linkage,
thresholds, representative weights/ties, scientific resources and container images
are unchanged. No production job, source, publication or work/cache was modified.

## Reporting benchmark

Local macOS arm64, locked Python 3.12.13. Valid synthetic native inputs and canonical
bundles: 64 genomes, 3,000 proteins each (192,000 proteins). Functional searches
were disabled. Baseline: v0.4.7 `db99951`. OS caches were not flushed; timing is
not a shared-storage forecast. Timed helper calls exclude interpreter, container
and scheduler startup. No native annotation searches were executed.

| Measurement | v0.4.7 | v0.4.8 full-table writer | v0.4.8 genome report |
| --- | ---: | ---: | ---: |
| Reporting wall time | 12.502 s | 6.320 s | 0.023 s |
| Peak observed SQLite file | 389.9 MB | 0 | 0 |
| Published report bytes | 115,214,608 | 115,214,608 | 92,522 |
| Process peak RSS | 48.7 MB | 52.5 MB | 23.5 MB |

All full-output TSVs were byte-identical. The genome report's four retained tables
were byte-identical to their baseline counterparts; omitted protein/detail/matrix
tables are an intentional output-contract change. Full-table reporting was about
2x faster. Genome reporting removed over 99.8% of measured reporting time and
99.9% of report bytes in this fixture. These are stage-level measurements. A reversed-order repeat during the broader
test run measured 27.058 s (baseline), 14.336 s (full writer) and 0.037 s (genome
report), again with identical shared tables. The full-writer ratio remained
approximately 1.9x despite substantial variation in absolute timings.

Reproduce with the locked environment:

```bash
python tests/benchmark_v048.py --baseline /path/to/v0.4.7 \
  --fixture /tmp/v048-report-benchmark --samples 64 --genes 3000
```

## ANI post-processing benchmark

A synthetic 2,500-genome matrix forms one complete-linkage cluster. Quality scores
are tied and ANI centrality varies. Baseline clustering and representative
selection perform their original separate matrix loads; the candidate shares one.
Both execute the real SciPy clustering and representative-scoring helpers.

- v0.4.7: 10.213 and 11.158 seconds.
- v0.4.8: 3.569 and 2.662 seconds.
- Cluster rows, representative identity, scores and detailed score traces match
  exactly, including the deterministic tie behaviour.
- Observed speedup range: 2.9-4.2x. Peak RSS remains approximately 274-277 MB;
  complete linkage's dense storage requirement is not removed.

```bash
python tests/benchmark_ani_postprocessing.py --baseline /path/to/v0.4.7 \
  --output /tmp/v048-matrix-benchmark --samples 2500
```

## Whole-run estimate and limits

The measured reporting reduction supports eliminating the reported large SQLite
spool entirely. It does not measure a production turnaround. If removed reporting
accounted for 20%, 50% or 80% of prior elapsed time, eliminating that component
alone would approach 1.25x, 2x or 5x overall speedup respectively. Overlap and shared
storage contention can change those estimates.

Native FastANI is unchanged. Final reference acceptance still freshly reads whole
providers; those full-content reads are not eliminated by this release.
Independent controllers do not share a persistent validation cache. Import batch
concurrency remains bounded. Full functional reports still validate their evidence
when rebuilt; this release caches the lightweight genome report, not arbitrary
mutable result directories. No old-version cache compatibility is promised.
