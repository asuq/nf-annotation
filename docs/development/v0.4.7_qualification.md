# v0.4.7 qualification

Validation dates: 2026-10-29 to 2026-10-30. Implementation base: v0.4.6,
`b1278586a745f20a4f754f3251eac4810dd38417`.

## Relocation and compatibility

- Unit fixtures move an entire QC/reference collection under another parent,
  remove the original location and retain identical manifest/link bytes and
  content digests. Later reference reuse, materialisation and annotation import
  remain valid without original paths or work directories.
- A real Nextflow fixture creates QC using the exact v0.4.4 source at
  `6b8c0b886f7a49c83b08f3cefbc58d44c392136c`, with controlled tool outputs. It moves
  those unchanged QC publications into the permanent provider tree and removes
  the old project, inputs and work. v0.4.7 reuses them without QC/gene-prediction
  tasks, including on subsequent relocated reuse and reannotation.
- The collection is copied with relative links preserved to another parent and
  the original is removed. Intermediate ANI views and eventually the providers
  are removed to prove successor independence from earlier views and explicit
  materialisation/reannotation independence from QC providers.
- Every original QC file remains byte-identical throughout reuse. A same-location
  worker-count change keeps ANI preparation and FastANI cached. No production
  analyses or data are used; this is not fresh native biological qualification.
- Missing/changed/retargeted providers, boundary escapes, internal aliases,
  circular references, legacy write attempts and derived ANI providers fail.
  Final acceptance also checks transient input snapshots without making those
  earlier ANI views permanent dependencies.

## Bounded validation and local timing

Real process-pool controls reach four workers with at most eight pending jobs.
Sample validation outputs and identity files are byte-identical at 1/2/4/8
workers, including additions, sanitisation collisions and retained failed/skipped
states. Errors are reported in input order and no accepted output is emitted
before validation completes. Reader controls retain mutation detection and
shared-provider deduplication.

`tests/benchmark_cohort_validation.py` creates 64 synthetic 5,000,000-base genomes
and complete controlled QC evidence, then performs read-only validation passes.
It compares the exact v0.4.6 preparation function with the candidate and asserts
identical output tables and run identities. Python 3.12.13 ran on local macOS
arm64 storage. Observed whole-preflight times were:

| Implementation | Workers | Seconds, in run order |
| --- | ---: | --- |
| v0.4.6 | 1 | 8.331 |
| Candidate | 1 | 7.618 |
| Candidate | 4 | 3.030 |
| Candidate | 8 | 2.496 |
| Candidate | 4 | 2.137 |
| Candidate | 1 | 8.100 |
| v0.4.6 | 1 | 7.797 |

Caches were not flushed and host load was uncontrolled. These are synthetic
local observations, not shared-storage or Slurm throughput guarantees. Global
metadata work, other serial validation loops, mandatory content reads and native
ANI computation remain. Multiple independent controllers do not share a trust
cache.

- The locked suite passed 648 tests with seven optional Docker skips.
- Twenty-five reader, process-pool and reference controls passed in the unchanged
  pinned Linux amd64 helper image with networking disabled and 8 CPUs / 2 GiB
  requested. The arm64 host used emulation; this is runtime compatibility
  evidence, not a Linux performance measurement.
- Helper integration, Viper configuration parsing, scoped Ruff, offline lock and
  diff whitespace checks passed. Viper retains its existing executor-scope warnings.

Existing release tags, production checkouts/jobs and scientific images/dependencies
remain unchanged. No production rerun is part of this release task.
