# v0.4.5 performance qualification

Date: 2026-10-28. Baseline: v0.4.4, commit
`6b8c0b886f7a49c83b08f3cefbc58d44c392136c`. Its tag and the production checkout
were not modified. The candidate keeps the scientific image references and
dependency versions unchanged.

## Synthetic benchmark

`tests/benchmark_ani_reuse.py` creates complete, reusable publications from
generated 1,600-nt genomes with one canonical protein each. Synthetic CheckM2
reports deliberately exclude every genome from ANI, isolating bookkeeping from
native pairwise analysis. Assembly statistics use the known fixture values.
No biological data, native scientific reruns or Slurm submissions are involved.
The real workflow, input/source checks, publication, cohort reporting and
aggregation run locally with a synthetic Docker shim. A separate real Linux
container smoke is described below.

Both versions receive identical inputs and the same 6,636-sample source. The
paired 512-sample result is:

| Measurement | v0.4.4 | Candidate |
| --- | ---: | ---: |
| Submitted Nextflow tasks | 2,065 | 27 |
| Monotonic local wall time, seconds | 196.76 | 135.50 |
| Work-directory regular files | 39,668 | 1,907 |
| Work-directory apparent bytes | 46,409,959 | 12,450,466 |
| Filesystem-reported allocated bytes in work | 160,473,088 | 18,501,632 |

This is 98.7% fewer submitted tasks and 31.1% less observed local wall time.
Twenty-six published TSVs are byte-identical, including the master/status tables,
protein/coordinate mappings and six functional matrices. All eight cohort 16S
FASTA/manifest files are also byte-identical, for 34 matched outputs. Runtime
provenance is expected to differ and is excluded from that comparison.

The candidate then runs three cumulative views through the same cache/work
context, each with a fresh independent publication:

| Requested genomes | Submitted tasks | Cached tasks | Monotonic wall time, seconds | Bundles reused |
| --- | ---: | ---: | ---: | ---: |
| 2,597 | 25 | 2 | 284.53 | 2,597 |
| 6,015 | 25 | 2 | 345.75 | 6,015 |
| 6,636 | 25 | 2 | 362.00 | 6,636 |

Each view uses eight import allocations and one disabled annotation plan.
Source validation and unchanged version reporting are cached. There are no
per-genome import, bundle-building, BUSCO-summary or annotation-planning tasks.
The acceptance assertion caps this synthetic workflow at 40 submitted tasks and
checks exact requested membership and row order.

On the host's clone-capable filesystem, the paired candidate view clones 16,896
payload files representing 8,752,128 logical bytes. The 6,636-sample view clones
218,988 payload files representing 113,435,784 logical bytes. The payload audit
records zero normal copies in those runs; metadata/channel/report writes still
occur. Logical clone sizes and filesystem block counts are not measurements of
exclusive physical storage or hardware I/O.

Wall times use the driver's monotonic clock, not sums of trace task durations.
These are individual local observations; cold/warm cache effects and concurrent
host load were not controlled. Small synthetic genomes qualify bookkeeping scale,
not real-genome byte throughput. An earlier 128-sample control against the large
source was slower initially (73.71 versus 62.02 seconds), exposing the cost of
the added complete content scan. Redundant filesystem lookups and repeated 16S
reads were subsequently reduced; integrity checks still require reading inputs.

The benchmark records code-file hashes, source-manifest identity, task breakdowns,
copy audits and workspace sizes in its JSON report. The performance measurements
use the normal link-staging path; subsequent path-alias validation and explicit
link-staging guards do not change that measured path. The release checks below
cover the final source.

## Integrity and portability controls

- Real Nextflow controls verify that the first unchanged resume caches cohort
  validation, while changed metadata is rejected by the separate resume guard.
  Nested source edits invalidate source validation; a unit control preserves
  file size and modification time while changing content.
- Disabled planning retains the exact prior sample/tool grid, including the
  unavailable disabled-eggNOG input count. Corrupted bundle contents still fail
  during aggregation.
- Bundle reuse checks producer/contract hashes and bindings to native inputs.
  Tests cover rebuilding an incompatible producer with the unchanged adapter,
  missing genetic codes, conflicting destinations, links, copy fallback and
  independence after deleting the source.
- The four 16S views match the original functions byte-for-byte across intact,
  partial, low-quality, unavailable and atypical cases, preserving input order.

A real Linux amd64 smoke used the unchanged Python helper image
`quay.io/asuq1617/python-scipy@sha256:30051a8fbc1fddbd6c5e1c10760699f40d2f5711e6640c36d4747a1882ef05c2`,
with networking disabled, one CPU and 1 GiB requested memory. On that filesystem
the helper correctly fell back to normal copying: 16 payload files / 3,805 logical
bytes. Every file matched the source, the existing bundle was reused and bundle
validation passed. This is a helper/runtime compatibility check, not a native
genome-analysis benchmark.

## Release gate

The complete locked suite passed 618 tests with seven optional Docker skips.
The initial run exposed an obsolete disabled-planner fixture expectation and
sandbox-blocked localhost HTTP fixtures; the expectation was updated and the
complete suite rerun with the existing test permission. nf-helper integration,
Viper configuration, scoped new-code lint and the offline lock check passed.
A fresh checkout of the committed release source is the final publication gate;
its outcome is recorded in the GitHub release notes.

## Remaining limits

Source fingerprinting still reads scientific payloads on every run. Receipt reuse
requires the same code/content and a retained Nextflow cache/work context;
independent parallel controllers do not share it automatically. Filesystems
without clone support require one normal payload copy per independent output.
The destination must be shared and writable from the task nodes. Large-genome
I/O, real Slurm throughput and native ANI's quadratic costs were not qualified
by these synthetic controls. See the [operator guidance](../ani_performance.md).
