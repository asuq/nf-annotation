# v0.5.5 qualification

## Assembly eligibility

The cohort uses the sum of the lengths of all staged contigs. An assembly below
20,000 bp gets `Low_quality=true` and `Assembly_Exclusion_Reason=assembly_below_20000_bp`
after per-sample prediction. The ordered master retains `Assembly_Bases`,
`CheckM2_Low_quality`, genetic code and native evidence. Per-sample status retains
the observed Prokka outcome. The Prodigal diagnostic reports its training
length, which includes padding for multi-contig input. See the
[released training reader](https://github.com/hyattpd/Prodigal/blob/v2.6.3/sequence.c#L20-L111). At 20,000 bp the other eligibility criteria apply.

The same size decision applies to cohort 16S FASTAs, ANI, AAI, eggNOG and
individual functional searches, including reannotation. The native bundle stays
available when a short assembly has predicted proteins. The cohort protein and
coordinate tables omit excluded proteins. The rule makes no change to
Prokka 1.15.6, Prodigal 2.6.3, their invocation or Prokka's mode-selection bug.

## Boundary and workflow checks

- A three-member Nextflow QC and clustering control tested 19,999 bp with both a
  successful and a failed Prokka outcome. Both excluded members retained their
  positions, original CheckM2 values and distinct prediction outcomes.
- A 20,000 bp control containing a one-base contig retained its original
  eligibility and appeared in the cohort 16S, ANI and AAI outputs.
- An enabled functional run searched the eligible member and retained the short
  member's native bundle byte-for-byte. Its proteins were absent from the
  cohort protein, coordinate and functional-summary tables.
- The size boundary also passed in the pinned Linux Python helper.

These integration controls run Nextflow with deterministic tool fixtures.
They validate workflow decisions and cache behaviour. A separate read-only
check applied the policy to an existing native QC publication.

## Recovering a v0.5.4 QC run

The cache transition used Nextflow 26.04.6, the helper at
`36c4148f975aa76008e48214f4fea1dad8e78f9b` and the same tool identities.
The Python helper image is
`quay.io/asuq1617/python-scipy@sha256:30051a8fbc1fddbd6c5e1c10760699f40d2f5711e6640c36d4747a1882ef05c2`.
The Prokka image is
`quay.io/asuq1617/prokka@sha256:d9ff718c4ea19621a16a78b9d21dc1d1073bcaadeef2348afa38c5544ed4564d`.

1. For an intact cache, run the new release with the original launch directory,
   work directory, configuration, manifests and runtime paths. Supply
   `-resume <original-session-id>`. In the three-sample transition, 43 tasks
   were cached. They included all 31 staging, scientific, genetic-code,
   bundle and assembly-statistics tasks checked. Eleven tasks ran for
   preflight, validation, taxonomy, eligibility, cohort tables and acceptance.
   Inspect the actual trace for the recovered cohort.
2. For a completed QC publication, run the new release in a separate checkout
   with `--pipeline_stage qc --update_from <v0.5.4-results> --outdir <fresh-results>`.
   Use the same sample and metadata manifests, domain, genetic-code policy and
   resource configuration. Choose a fresh work directory. This route also
   works independently of the original Nextflow cache. The three-sample test
   preserved all bundle manifests and the source master bytes. It ran import,
   assembly-statistics and reporting tasks with zero new per-sample predictions.

The publication route permits other controllers to continue using the original
checkout. Verify the exact input identity, ordered membership and the new
assembly fields before promoting the recovered publication. A short member with
a recorded nonzero prediction exit retains `prokka_status=failed`, an unavailable
CDS count and downstream exclusion. Its presence in a QC publication does not
qualify it as a usable protein bundle. Refresh QC before reannotating a source
that predates the length decision.

## Release gates

The mixed and all-excluded functional cohort tests passed. The latter produced
a complete publication with two retained master rows and an empty protein table.
Repository-wide Ruff, formatting and ty checks, helper integration, and Viper
configuration checks passed. Across the complete 740-case inventory, 733 tests passed after targeted repairs
and seven opt-in container tests were skipped. The Linux helper boundary control
ran separately. One fixture needed its original ANI identities restored after
its length increased. One local integration timed out and passed its isolated
rerun. Two reference tests loaded an older synthetic publication format and
passed with the measured fixture length. Successful unrelated cases from the
first test process were retained when the remaining inventory resumed.
